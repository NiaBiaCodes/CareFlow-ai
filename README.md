# CareFlow integrated synthetic demo

CareFlow preserves PR1 chart review, six scenarios, validated drafts, cited reference comparisons, and SurrealDB history. **Live Daytona + model + Anchor** adds an actual OpenAI call inside Daytona, strict fact validation, Anchor browser actions, clinician approval, simulated submission, Phoenix traces, and explicit cleanup. All records and receipts are fictional; pharmacy fills remain unknown.

## Startup

Use Python 3.11+ and Docker Desktop. From `C:\Users\piush\Desktop\CareFlow-ai`:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.lock.txt
if (!(Test-Path .env)) { Copy-Item .env.example .env }
python scripts/configure_local_demo.py
docker compose -f compose.yaml -f compose.phoenix.yaml up -d
python scripts/seed_surreal.py
```

Preserve the existing `.env` and database volume. Seeding restores baseline chart IDs while retaining task history. If the database is still starting, wait and retry. `docker compose down` retains the volume; do not add `-v`.

Configure ignored `.env`:

| Variable | Purpose |
| --- | --- |
| `SURREAL_HTTP_URL`, `SURREAL_NAMESPACE`, `SURREAL_DATABASE`, `SURREAL_USER`, `SURREAL_PASSWORD` | Existing local database; default URL `http://127.0.0.1:8001` |
| `DAYTONA_API_KEY` | Sandbox lifecycle and execution |
| `OPENAI_API_KEY` or `LLM_API_KEY`, `LLM_MODEL` | OpenAI Responses provider with structured output support |
| `ANCHOR_API_KEY` | Remote browser sessions |
| `PORTAL_SIGNING_KEY` | At least 32 characters; generated by setup script |
| `MOCK_PAYER_BASE_URL` | Remote HTTPS origin forwarding only port 8002 |
| `PHOENIX_COLLECTOR_ENDPOINT` | App OTLP HTTP endpoint, e.g. `http://127.0.0.1:6006/v1/traces` |
| `PHOENIX_WORKER_COLLECTOR_ENDPOINT` | OTLP endpoint reachable from Daytona; never development localhost |
| `PHOENIX_API_KEY`, `PHOENIX_WORKER_API_KEY` | Collector Bearer keys when required |
| `PHOENIX_PROXY_TOKEN` | Generated key for optional local OTLP relay |

`DAYTONA_SNAPSHOT` optionally selects a prepared Python snapshot. `CAREFLOW_EXECUTION_TIMEOUT` defaults to 180 seconds. The account-listed model selected for this workspace is `gpt-4.1-mini-2025-04-14`; the runtime always reads `LLM_MODEL` and has no fallback model.

Run each command in a separate activated terminal:

```powershell
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
python -m uvicorn app.edge:app --host 127.0.0.1 --port 8002
python -m uvicorn app.telemetry_edge:app --host 127.0.0.1 --port 8003
```

Open [CareFlow](http://127.0.0.1:8000) and [Phoenix](http://127.0.0.1:6006). Keep clinician port 8000, database 8001, and Phoenix UI 6006 private. Use one Uvicorn worker. Restart processes after `.env` changes. A restart retains outcomes/resource IDs but never automatically replays interrupted paid work; use **Recover state / retry resource cleanup** before retrying.

## Remote portal and telemetry

Reuse an existing restricted HTTPS portal and hosted collector if available. Otherwise install `cloudflared` from [Cloudflare's official downloads](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/downloads/) and run two temporary tunnels:

```powershell
cloudflared tunnel --url http://127.0.0.1:8002 --protocol quic --edge-ip-version 4 --no-autoupdate
cloudflared tunnel --url http://127.0.0.1:8003 --protocol quic --edge-ip-version 4 --no-autoupdate
```

Set `MOCK_PAYER_BASE_URL` to the first printed HTTPS origin. Set `PHOENIX_WORKER_COLLECTOR_ENDPOINT` to the second origin plus `/v1/traces`; set `PHOENIX_WORKER_API_KEY` to the existing local `PHOENIX_PROXY_TOKEN`. Restart the app. Temporary origins change on tunnel restart and have no uptime guarantee. Never put keys in URLs or tracked files.

The payer boundary permits only scoped synthetic request routes and two static assets. Task access requires a short-lived HMAC Bearer capability. It blocks clinician approval, `/api`, docs, source viewers, and database access. The separate relay accepts only authenticated protobuf `POST /v1/traces` up to 1 MiB; it exposes no Phoenix UI/query API.

On Windows with an existing TLS inspection certificate trusted by Windows, Python clients may need the same trust roots:

```powershell
python scripts/configure_windows_trust.py
```

This opt-in script writes an ignored CA bundle from existing Windows roots and configures `SSL_CERT_FILE`. TLS verification stays enabled; no new system root is installed. Restart the app afterward.

```powershell
python scripts/check_integrations.py --require-ready
```

This checks configuration presence and SDK versions, not provider connectivity. See `VERIFICATION.md` for actual integration evidence.

The Daytona organization must permit outbound access to Anchor, the payer origin,
and the worker collector. Tier 1/2 policies can block these even when OpenAI and
PyPI work; a sandbox allow list cannot override the organization policy. See
[Daytona network limits](https://www.daytona.io/docs/en/network-limits/).
Anchor also needs an available credits balance. These two account requirements
were resolved during the live verification; their failed attempts remain saved.

## Shortest click sequence

1. Select **Morgan Demo**, **missing referral**, and **Live Daytona + model + Anchor**. Click **Review patient records**. Wait for a validated live amlodipine answer and `MISSING_REFERRAL`; browser creation is blocked.
2. Select **corrected referral**, choose live execution again, and review. A new corrected task preserves the failed attempt. Wait for Anchor to fill every field, read every value back, save revision 1, and terminate browser and sandbox. Review the values, evidence, and limitations.
3. Click **Approve exact draft revision 1**, then **Submit approved draft through Anchor**. A new short execution reopens and verifies the exact approved draft. Observe one **Simulated receipt**. Repeated submission returns that receipt.
4. In Phoenix open **careflow-demo**, select the task trace, and inspect model, validation, browser, approval, receipt, and cleanup attributes. Worker trace context joins the application execution. Expected referral blocks are validation results; API failures are execution errors.
5. Select **Avery Demo**, **happy**, and live execution for lisinopril 10 mg to 20 mg and unchanged metformin. Reopen previous outcomes from history after resource deletion or an app restart.

The reference option remains usable without provider keys. It is labelled separately and never substitutes for a failed model response. Reference tasks cannot be approved or submitted.

## Boundaries and persistence

The server builds selected context using fixed tables and bound query parameters. Patient ownership is checked before upload. The worker receives a selected context and code whitelist, never the full dataset, `.env`, database credentials, or expectation oracle. The live model gets dated reconciliations and supporting notes. Structured output must match exact medication facts, dates, patient identity, and complete source sets in both worker and server. Unsupported output is rejected without fallback.

Anchor performs actual DOM fills, readback, and clicks; direct HTTP is limited to preflight and audit callbacks. The server requires readback evidence before accepting a verified draft. Approval binds task, patient, current context, exact revision, and full draft hash to a one-time private review nonce. Relevant record/draft changes invalidate approval. Submission capability is withheld until review. Receipt insertion and task transition use one atomic transaction and idempotency key. An ambiguous click timeout consults durable state before retrying.

Worker telemetry flushes before deletion. Explicit Anchor termination is confirmed through status/404, and Daytona deletion waits for confirmation. Cleanup failures retain IDs and block review. Recovery rediscovers by task labels/tags, retries cleanup, and reloads saved outcomes through a new repository. A telemetry failure never discards an otherwise saved result.
